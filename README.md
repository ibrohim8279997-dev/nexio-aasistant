# Кимо и агенты

Мультиагентная система в Telegram на одном телефоне-сервере (Termux + Debian, без Docker, long polling).

- **Кимо** (`kimo`) — главный агент и диспетчер. Сам ведёт расходы, задачи и напоминания, остальную работу передаёт другим агентам.
- **Создатель агентов** (`agent_builder`) — по вашему описанию составляет карточку нового агента.
- **Ассистент** (`assistant`) — универсальный помощник: отвечает на вопросы, ищет в интернете (browser search Groq), а нужные данные запрашивает у Кимо.

У каждого агента свой Telegram-бот и свой процесс (`python run_agent.py <имя>`) в отдельном окне tmux, поэтому падение одного не задевает остальных. Все агенты используют один репозиторий, один venv, одну SQLite в режиме WAL и один `GROQ_API_KEY`.

## Что умеет Кимо (было и осталось)

| Раздел | Что умеет |
|---|---|
| Задачи | Текстом или голосом («завтра в 15:00 позвонить маме»): «Сегодня»/«Завтра», выполнено, перенос, удаление, напоминания |
| Расходы | Суммы в UZS и USD, категории, курс ЦБ (cbu.uz, кэш 1 час), итоги за день, 7 и 30 дней |
| Статистика | Графики расходов и задач, трекер выполнения и серия дней подряд |
| Подписка | Telegram Stars, 250 ⭐ за 30 дней. **Выключена флагом** `SUBSCRIPTION_ENABLED=false`, Click — выключенная заготовка |

## Как устроено

```
Владелец ──голос/текст──▶ Кимо (группа или личка)
                           │  Whisper → gpt-oss-120b решает, чья это задача
                           ├─ своя (расходы, задачи) → выполняет сам
                           ├─ чужая → пишет задание в tasks_queue → «👉 Задачу взял Ассистент»
                           └─ неясно → один короткий вопрос
Агент (свой процесс) ◀── опрашивает tasks_queue раз в 1,5 с, забирает задание атомарно,
                          выполняет и отвечает в группу от своего имени реплаем на исходное сообщение
```

- **Конфиг агента** хранится в таблице `agents`: имя, роль, системный промпт, модели (провайдер, текстовая модель, Whisper, поиск), разрешённые таблицы и команды, запреты. Стартовые карточки лежат в `agents/*.json` и попадают в БД при первом запуске. Дальше источник правды — БД.
- **Идентичность.** В промпт каждого агента подставляются его имя, роль, запреты и список остальных включённых агентов с ролями, всё из таблицы `agents`. На вопрос «как тебя зовут» Кимо отвечает «Кимо».
- **Права на таблицы** проверяются в слое доступа к БД (`bot/agents/access.py`, обёртка `ScopedDB`), а не только в промптах:
  - агент получает только таблицы из `allowed_tables`;
  - таблицы `expenses`, `payments` и `secrets` доступны только Кимо, что бы ни было написано в конфиге;
  - у нового агента по умолчанию нет доступа ни к одной таблице, кроме собственных `agent_<имя>_*`;
  - на запросы других агентов через шину Кимо данные о расходах не выдаёт.
- **Шина заданий** — таблица `tasks_queue`. Поле `depth` растёт на 1 при каждой передаче между агентами. Если передач больше 3, задача получает статус `failed` и возвращается владельцу с пояснением (защита от зацикливания).
- **В группе** исполняются только сообщения владельца (`ADMIN_ID`). Сообщения других участников игнорируются. Если в группе появляется токен, он тут же удаляется. Если сообщение адресовано другому агенту (упоминание `@бот` или реплай на его сообщение), Кимо его не перехватывает.

## Установка (Termux + Debian)

### 1. Termux и Debian

```bash
# Termux (из F-Droid)
pkg update && pkg upgrade -y
pkg install -y proot-distro openssh tmux termux-api
termux-wake-lock
proot-distro install debian
proot-distro login debian
# Debian
apt update && apt install -y python3 python3-venv python3-pip git tmux
```

Отключите для Termux оптимизацию батареи: Настройки Android → Приложения → Termux → Батарея → «Без ограничений».

**SSH.** В Termux задайте пароль (`passwd`) и запустите `sshd`. С компьютера: `ssh -p 8022 <любое_имя>@<IP_телефона>`.

### 2. Код

```bash
cd ~
git clone https://github.com/ibrohim8279997-dev/nexio-aasistant.git
cd nexio-aasistant
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
```

### 3. Боты в @BotFather (делается вручную, по API нельзя)

1. Создайте три бота командой `/newbot`: для Кимо, для Ассистента и для Создателя агентов.
2. **Кимо: отключите privacy mode.** `/mybots` → бот Кимо → Bot Settings → Group Privacy → **Turn off**. Иначе Кимо видит в группе только команды и упоминания. Если бот уже был в группе, удалите его и добавьте заново, чтобы настройка применилась.
3. У остальных агентов privacy mode оставьте включённым: в группе они отвечают на упоминание `@бот` и на реплай, а задания получают через шину.
4. Создайте группу и добавьте в неё всех ботов. **Сделайте Кимо администратором с правом удалять сообщения**, чтобы он мог стирать случайно отправленные в группу токены.
5. Каждому боту отправьте `/start` в личке. Без этого бот не сможет написать вам первым.

### 4. `.env` и токены

```bash
cp .env.example .env
python gen_key.py        # строку ENCRYPTION_KEY=... вставьте в .env
nano .env                # GROQ_API_KEY, ADMIN_ID
chmod 600 .env
```

Токены ботов лучше хранить зашифрованно в БД, а не в `.env`:

```bash
python manage.py agents set-token kimo            # ввод скрыт, токен шифруется Fernet в таблице secrets
python manage.py agents set-token assistant
python manage.py agents set-token agent_builder
```

Можно и через `.env`: `KIMO_TOKEN`, `ASSISTANT_TOKEN`, `AGENT_BUILDER_TOKEN`. Старая переменная `BOT_TOKEN` по-прежнему работает для Кимо.

Порядок поиска токена: переменная из `.env`, затем `secrets`, для Кимо в последнюю очередь `BOT_TOKEN`.

| Переменная | Значение |
|---|---|
| `GROQ_API_KEY` | один ключ на всех агентов (https://console.groq.com/keys) |
| `ADMIN_ID` | ваш Telegram ID. Команды исполняются только от него |
| `ENCRYPTION_KEY` | ключ Fernet. **Сохраните копию**, без него токены в БД не расшифровать |
| `DB_PATH` | `data/bot.db` |
| `SUBSCRIPTION_ENABLED` | `false` — бот личный; `true` — включена продажа подписки Stars |
| `SEARCH_ENABLED` | `true` — веб-поиск разрешён агентам, у которых в конфиге `"search": true` |
| `CLICK_ENABLED` | `false` (Click — заготовка) |

Модели и провайдер берутся из конфига агента (`models`), а не из кода и не из `.env`.

### 5. Запуск всех агентов

```bash
chmod +x run.sh run_all.sh
./run_all.sh              # все включённые агенты из таблицы agents, каждый в своём окне tmux (сессия agents)
./run_all.sh status
./run_all.sh stop | restart
tmux attach -t agents     # окна агентов: Ctrl+B, затем номер окна; выйти — Ctrl+B, затем D
```

Один агент:

```bash
./run.sh start assistant      # новое окно tmux; при падении агент перезапустится через 5 с
./run.sh stop assistant
./run.sh restart assistant
./run.sh logs assistant       # logs/assistant.log
./run.sh fg assistant         # в текущем терминале (отладка)
```

Коды выхода `run_agent.py`:

| Код | Значение | Что делает `run.sh` |
|---|---|---|
| 0 | штатная остановка | перезапускает |
| 1 | падение | перезапускает |
| 2 | ошибка конфигурации (нет токена, плохой `.env`) | не перезапускает |
| 3 | агент выключен или не найден | не перезапускает |

Ошибки ищите в `logs/<агент>.log`.

```bash
chmod 600 data/bot.db*
```

**Автозапуск после перезагрузки (Termux:Boot):**

```bash
mkdir -p ~/.termux/boot
cat > ~/.termux/boot/start-agents.sh <<'EOF'
#!/data/data/com.termux/files/usr/bin/sh
termux-wake-lock
proot-distro login debian -- bash -c "cd ~/nexio-aasistant && ./run_all.sh"

chmod +x ~/.termux/boot/start-agents.sh
```

### Переход со старой версии (один бот)

```bash
./run.sh stop 2>/dev/null; tmux kill-session -t tgbot 2>/dev/null   # остановить старого бота
git pull && . .venv/bin/activate && pip install -r requirements.txt
python manage.py db backup                                          # ручной бэкап (автоматический тоже будет)
./run_all.sh
```

При первом запуске применяется миграция №2: она добавляет таблицы `agents` и `tasks_queue`. Перед миграцией делается бэкап `data/backups/bot-<дата>-before-v2.db`. Расходы и задачи миграция не трогает.

### Обновление до версии с миграцией 3 (имена, heartbeat, аудит)

```bash
./run_all.sh stop
python manage.py db backup                  # ручной бэкап; перед миграцией он делается и автоматически
git pull && . .venv/bin/activate && pip install -r requirements.txt
./run_all.sh                                # Кимо первым применяет миграцию №3
python manage.py agents list                # проверьте имена
python manage.py agents rename <id_миди> Миди
python manage.py check-search               # проверка веб-поиска Groq боевым ключом
```

Миграция 3 добавляет колонки в `agents` (`display_name`, `role_description`, `access_role`, `created_by`, `last_seen`, `status`, `status_detail`, `last_error`) и в `tasks_queue` (`delivered`, `reply`), таблицы `audit_log`, `pending_actions` и `agent_assistant_notes`. Старые задания помечаются доставленными, чтобы их результаты не пришли повторно. Описания ролей копируются в `role_description`, ничего не теряется. Агенты, кроме трёх стартовых, записываются как созданные Мимо (`created_by = agent_builder`). У Кимо убирается `secrets` из разрешённых таблиц.

## Добавление агента

**Через Кимо (основной способ):**

1. Скажите или напишите Кимо: «Создай агента для …: что делает, что можно, что нельзя, насколько всё конфиденциально».
2. Кимо передаёт описание создателю агентов. Тот составляет карточку: имя, роль, промпт, нужен ли Whisper и поиск, предлагаемые права, запреты. Модель только **предлагает**: расходы, платежи и секреты в карточку не попадают никогда.
3. Кимо показывает карточку. Вы выбираете: «Да, с предложенными правами», «Да, без доступа к таблицам» или «Отмена». Без подтверждения агент не запускается.
4. Создайте бота в @BotFather и **пришлите токен Кимо в личку**. Кимо удалит сообщение и сохранит токен зашифрованным. В группе токены не принимаются.
5. Кимо запустит агента в новом окне tmux, проверит, что тот отвечает через шину, и сообщит: «Агент работает».

Команды владельца в Кимо:

| Команда | Что делает |
|---|---|
| `/agents` | список агентов и их статус |
| `/agentperm имя tasks,rates_cache` | задать таблицы агенту (`-` — без доступа) |
| `/agenton имя`, `/agentoff имя` | включить и запустить / выключить и остановить |
| `/agenttoken имя токен` | передать токен, если его ждут несколько агентов |

**Вручную:**

```bash
cp agents/assistant.json agents/staff_bot.json && nano agents/staff_bot.json   # name, role, prompt, models, права
python manage.py agents add agents/staff_bot.json      # добавится выключенным
python manage.py agents set-token staff_bot
python manage.py agents enable staff_bot
./run.sh start staff_bot
```

Прочие команды: `python manage.py agents list | show <имя> | sync [имя] | enable | disable`. `sync` перечитывает `agents/*.json` в БД и сохраняет `enabled` и `bot_username`.

## Очередь заданий: контекст, ответ в чат, доставка один раз

- У каждого задания всегда есть `chat_id`. Если создатель его не указал, берётся чат владельца (`ADMIN_ID`), а в `payload` ставится пометка `chat_fallback`.
- Задание типа `ask` несёт контекст: кто спрашивает (`from`, `from_name`), исходный запрос владельца, о чём и что нужно. Если создатель контекст не дал, шина дополняет его (`context.auto = true`).
- `reply` по умолчанию `true` у `ask` (ответ нужен вызывающему) и `false` у служебных заданий (`ping`, `build_card`).
- Кто отправляет ответ в чат (`payload.deliver_by`):
  - `sender` — по умолчанию у `ask`. Создатель задания сам опрашивает свои завершённые задания (`status` done/failed, `delivered = 0`), отправляет результат реплаем на исходное сообщение от своего имени и ставит `delivered = 1`. Повторной отправки нет: флаг ставится атомарно, даже если у агента два цикла.
  - `inline` — создатель ждёт результат в этом же процессе. Если не дождался, результат всё равно придёт позже с пометкой «ответ пришёл с опозданием».
  - `receiver` — передача задачи в группе: ответ реплаем отправляет исполнитель, а Кимо коротко сообщает, кто взялся.
- Если Кимо не понял задание, он возвращает `failed` с причиной в `result`, а уточняющий вопрос уходит владельцу в личку.
- Защита от зацикливания сохранена: `depth` растёт на 1 при каждой передаче, после 3 передач задание получает `failed`, а владельцу приходит пояснение.

## Голосовой звонок (Linphone по Tailscale)

Вы звоните из Linphone на сервер и разговариваете с Кимо голосом. Кимо сам звонит вам по заданиям агентов. Всё внутри Tailscale: без публичных адресов и платных провайдеров.

```
Linphone ─ SIP/UDP ─▶ voice_sip.py (pjsua2) ─ фразы (VAD) ─▶ Whisper (Groq) ─▶ tasks_queue ─▶ Кимо
Linphone ◀─ звук ──── voice_sip.py ◀─ edge-tts ◀──────────── ответ Кимо ◀─────── tasks_queue
```

- `voice_sip.py` отвечает только за звонок и звук. Решения принимает Кимо через очередь заданий (`voice_command`, защита `depth` сохранена), с теми же правами и тем же подтверждением, что и сообщение в Telegram.
- **Опасные действия** (остановка агента, запись в чужую таблицу, права) подтверждаются только текстом «да» в Telegram. Голосовое «да» ничего не подтверждает: Кимо в ответ скажет, что отправил запрос в Telegram.
- В звонке Кимо говорит коротко. Длинные ответы, таблицы, логи и ссылки не читаются: звучит «подробности отправил в чат», а полный текст сразу приходит в Telegram. После звонка в Telegram приходит расшифровка всего разговора.
- Языки: русский (Светлана или Дмитрий) и узбекский (Мадина или Сардор). Голос выбирается по языку **ответа**, а не вопроса.
- Перебивание: если вы заговорили, пока Кимо говорит, озвучка сразу останавливается.
- Если Groq или edge-tts недоступны, Кимо скажет «сейчас не могу ответить» (а если озвучить нечем, даст сигнал и напишет в Telegram), причина пишется в `logs/voice_sip.log`.
- **Голосовые сообщения в Telegram** работают отдельно от звонка: отправьте голосовое Кимо или Мими и получите текст и озвученный ответ (ogg opus). Отключить: `VOICE_TG_REPLY=false`.

### Установка на сервере

```bash
# окружение, где собран pjsua2 (у вас ~/sipenv)
~/sipenv/bin/pip install -r requirements-voice.txt     # webrtcvad требует setuptools<81, он уже указан
pip install -r requirements.txt                        # в основном окружении добавился edge-tts (голосовые ответы в Telegram)
ffmpeg -version                                        # нужен ffmpeg с libopus
nano .env                                              # SIP_USER, SIP_PASSWORD, SIP_BIND_ADDRESS, SIP_CALLBACK_URI
chmod 600 .env
```

- `SIP_BIND_ADDRESS` — адрес Tailscale этого сервера (100.x.x.x). SIP слушает только его и `127.0.0.1`. Другие адреса программа не принимает.
- `SIP_PASSWORD` не короче 8 символов. Логин и пароль нигде не логируются.
- `SIP_CALLBACK_URI` — куда звонит Кимо: `sip:имя@адрес-Tailscale-устройства-с-Linphone:порт`.

**Быстрая проверка работающей службы** (сама звонит на неё с паролем, Linphone не нужен):

```bash
~/sipenv/bin/python scripts/sip_probe.py
```

Если итог «сервер принимает звонки с паролем», дело в настройке Linphone. OPTIONS без ответа — не ошибка.

**Полная самопроверка без Linphone** (сначала остановите службу):

```bash
./run.sh stop voice_sip
~/sipenv/bin/python voice_sip.py --selftest
```

Самопроверка звонит сама себе: неверный пароль должен дать 403, верный соединяется, звук идёт в обе стороны, выводится список кодеков (есть ли opus). Пришлите вывод целиком, если что-то не прошло.

**Запуск:**

```bash
python manage.py agents enable voice_sip     # служба по умолчанию выключена
./run.sh start voice_sip                     # отдельное окно tmux, окружение ~/sipenv (VOICE_VENV меняет путь)
./run.sh logs voice_sip
```

### Настройка Linphone (Android)

1. Добавьте SIP-аккаунт: имя пользователя и пароль из `.env` (`SIP_USER`, `SIP_PASSWORD`), домен `100.x.x.x:5060` (адрес Tailscale сервера), транспорт **UDP**, регистрацию **выключите**. Без аккаунта с паролем Linphone не ответит на запрос пароля.
2. Звоните на `sip:SIP_USER@100.x.x.x:5060`. Первый запрос без пароля получает 401 с вызовом, это нормально, Linphone повторит запрос с паролем.
3. Для звонков Кимо к вам в настройках Linphone → «Сеть» зафиксируйте порт UDP (например 5060). `SIP_CALLBACK_URI` = `sip:любое_имя@<Tailscale-адрес-телефона-с-Linphone>:5060`.
4. **Если звонок сбрасывается, а в логе службы «401 … Authorization нет» без второй попытки** — Linphone не подставил пароль:
   - проверьте, что регистрация у аккаунта выключена (при включённой регистрации аккаунт «не активен», и Linphone звонит без пароля; «IO error» при создании аккаунта — это как раз упавшая регистрация, у сервера нет регистратора);
   - следите за уведомлением Linphone «требуется аутентификация» во время звонка: введите там пароль один раз, Linphone запомнит его с правильным realm;
   - если не помогло, задайте в `.env` realm равным домену из Linphone: `SIP_REALM=100.119.11.24`, затем `./run.sh restart voice_sip`.
5. Отключите для Linphone оптимизацию батареи и разрешите работу в фоне. Если Android усыпил приложение, звонок не дойдёт: это не ошибка кода. Причина пишется в лог, а суть сообщения придёт в Telegram.

### Исходящие звонки

- Любой агент просит звонок заданием `call_owner` (причина и необязательно `urgent`). Звонит **только Кимо**: он проверяет правила и отправляет `place_call` службе, а она принимает такие задания только от Кимо.
- Правила: не больше одного звонка за 10 минут; ночью (23:00-07:00 по Ташкенту) звонят только срочные; не ответили за 30 секунд, отбой и сообщение в Telegram с причиной. Если ночью или из-за лимита не звоним, суть всё равно приходит в Telegram.
- Агентам звонок доступен через планировщик (`call_owner`), отключить для конкретного агента можно `can_call_owner=false` в его конфиге.

### Что пишется и где

- `logs/voice_sip.log`: каждый звонок (время, направление, длительность, причина завершения). Звук на диск не пишется. Запись включается только флагом `SIP_RECORD_CALLS=true` и идёт в `data/calls/` (звук звонящего, права 600).
- `audit_log`: `voice_call` (звонок), `voice_phrase` (время, текст фразы, какой агент ответил), `voice_call_out` (исходящая попытка).
- **Безопасность:** порт 5060 наружу не открывается; пять неверных попыток входа подряд с одного адреса блокируют его на 15 минут; пароль проверяется digest (MD5, nonce с ограниченным сроком); одновременно идёт один звонок.

## Живость агентов, таймауты и отчёт «кто работает»

- **Heartbeat.** Каждый агент раз в 20 с пишет в таблицу `agents`: `last_seen`, `status` (`online` / `busy` / `error`), последнюю ошибку (токены и ключи вырезаются). Агент без свежего `last_seen` дольше 90 с считается `offline`. При штатной остановке агент сразу пишет `offline`.
- **Лимит Groq (429).** Агент ставит `busy` с причиной `rate_limit` и временем повтора, Кимо это видит. Запрос повторяется по `retry-after` до двух раз, после чего владельцу приходит сообщение (не чаще раза в 5 минут).
- **Watchdog в Кимо** (раз в 10 с):
  - задание `new` для offline-агента закрывается как `failed` примерно через 10 с;
  - если агент жив, но не взял задание, оно закрывается за 60 с (`task_timeout_s` в конфиге агента; у Мими 180 с из-за веб-поиска);
  - зависшее `taken` закрывается через `taken_timeout_s` (по умолчанию в три раза больше).
  Владельцу сразу приходит причина: offline, лимит Groq или ошибка. Для offline-агента добавляется предложение перезапуска.
- **Перед передачей задачи** Кимо проверяет `last_seen`. Если агент offline, задание не создаётся, а Кимо называет причину и предлагает перезапуск.
- **Отчёт.** Скажите Кимо «кто работает» или «покажи логи Миди за 30 минут»:
  - список агентов по именам со статусом и временем `last_seen`;
  - для проблемных агентов последняя ошибка и 10 последних строк лога;
  - очередь по статусам для каждого агента и последние 5 неудачных заданий с причиной.
  Мимо показывает то же, но только по созданным им агентам.

## Роли, подтверждения и аудит

- Роль хранится в `agents.access_role`, а не в коде, и проверяется при каждом запросе: `admin` (Кимо), `creator` (Мимо), `agent` (остальные).
  - **Кимо** видит структуру и данные таблиц всех агентов, их логи и статусы. Расходы видит только он.
  - **Мимо** видит только агентов с `created_by = agent_builder`: их таблицы, логи и очередь. Расходов, платежей, секретов и чужих агентов у него нет.
  - **Обычный агент** работает только со своими таблицами `agent_<имя>_*` и теми, что выданы в `allowed_tables`.
- **Секреты.** Значения не видит никто: ни агенты, ни Кимо. В отчётах и логах токены заменяются на `***`, доступны только имена секретов.
- **Подтверждения.** Остановка, запуск, перезапуск, смена имени, роли, промпта, моделей, таблиц и команд, а также запись в чужую таблицу выполняются только после «да» от `ADMIN_ID`:
  - подтверждение приходит в личку кнопками «Да» / «Нет» (можно ответить текстом «да» или «нет»);
  - срок действия 15 минут, повторное нажатие ничего не делает;
  - расширение прав (новые таблицы или команды) всегда отдельное подтверждение, расходы, платежи и секреты выдать нельзя.
- **Аудит.** Каждое обращение пишется в `audit_log`: кто, что, когда, над кем и результат (в том числе отказы). Посмотреть: `sqlite3 data/bot.db "select ts,actor,action,target,result from audit_log order by id desc limit 20"`.
- Команды владельца в Кимо: `/agents`, `/agentperm`, `/agenton`, `/agentoff`, `/agentname имя Имя`. То же можно сказать голосом или текстом, например «перезапусти Миди» или «покажи логи Мими».

## Имена агентов

- У агента есть технический идентификатор `name` (процесс, `from_agent` и `to_agent` в очереди, имена таблиц), он **не меняется**, и человеческое имя `display_name`. Описание роли хранится отдельно в `role_description`.
- Кимо и Мимо называют агентов по `display_name`, а искать их можно и по `display_name`, и по идентификатору, регистр не важен («передай Мими» уходит в очередь к `assistant`).
- Стартовые имена задаёт миграция: Кимо, Мимо (`agent_builder`), Мими (`assistant`). Для остальных агентов описание вместо имени именем не считается, поэтому имя нужно задать один раз:

  ```bash
  python manage.py agents list                      # найдите идентификатор агента встреч
  python manage.py agents rename <id_миди> Миди     # запишется в audit_log
  ```

  Либо скажите Кимо: «назови агента <id> Миди», тогда имя придёт на ваше подтверждение.
- При создании нового агента владельца спрашивают имя (1-3 слова, до 30 символов). Агент не запускается, пока имя не подтверждено «да» и не получен токен.
- Менять `display_name` и описание роли может Кимо у любых агентов, Мимо только у созданных им, и всегда через подтверждение.

## Самолечение

«Почему Миди не работает» или «диагностируй Миди» запускает диагностику.

1. Кимо читает `last_seen`, ошибку из heartbeat, последние `failed`-задания и лог агента. Причину ищет по конфигурации агента и по известным признакам в логах. Если причины нет, так и пишет, ничего не выдумывает.
2. Владельцу приходит полный отчёт: что сломалось (симптом, причина, таблица и поле или файл и строка), как определил, что хочет изменить (diff), зачем, что может затронуть, как проверит.
3. Только после «да» в личке Кимо:
   - делает бэкап конфигурации в `data/backups/agent-<имя>-<дата>.json` и пишет в `audit_log`;
   - вносит правку **только в конфигурацию этого агента** (поля `models`, `config`, `allowed_tables`, `allowed_commands`);
   - перезапускает только процесс этого агента в отдельном окне tmux;
   - ждёт heartbeat до 60 с и отправляет `ping`;
   - если агент не поднялся или `ping` не прошёл, возвращает конфигурацию из бэкапа, запускает агента на старой версии и присылает отчёт.
4. Не больше 2 попыток исправления одного агента в час, после этого только отчёт. Кимо и Мимо автоматически не чинятся: для них готовится diff, а применяет его владелец. Общий код (`bot/**`), слой доступа, шифрование и `run_all.sh` не правит никто из агентов, а произвольные shell-команды из текста модели не выполняются.

## Лимиты Groq (бесплатный план)

| Модель | Запросов в минуту | Запросов в день | Токенов в минуту | Токенов в день |
|---|---|---|---|---|
| `openai/gpt-oss-120b` | 30 | 1000 | 8 000 | 200 000 |
| `whisper-large-v3-turbo` | 20 | 2000 | — | — |

Лимит общий на все агенты, потому что ключ один. Как бот с ним работает:

- **Учёт:** каждый процесс сам считает запросы и токены и читает заголовки `x-ratelimit-remaining-*` из ответов Groq. Если токенов почти не осталось, агент ждёт сброса окна.
- **Ответ 429:** агент ждёт `retry-after` (до 20 с) и повторяет запрос. Если ждать дольше, вы получите сообщение, через сколько попробовать снова.
- **Поиск:** у ассистента — не больше одного шага поиска на запрос. Число поисков внутри шага ограничено промптом (`max_searches` в конфиге, по умолчанию 2) и `reasoning_effort=low`.
- **Замер расхода:** каждый вызов модели пишется в `logs/usage-<агент>.log`: prompt/completion/total токены, число поисков, `x-ratelimit-remaining-tokens`, `x-ratelimit-remaining-requests`. Тексты и ключи туда не попадают. Пример: `grep "search=True" logs/usage-assistant.log`.

## Рассылки по расписанию

**Ограничения Telegram Bot API (Кимо их не обходит):**
- Бот **не видит список контактов** владельца. Получатели: чаты, где клиент уже писал вам (Кимо запоминает их при первом Business-сообщении) и люди, которые сами подписались по ссылке на бота. Ручной ID принимается, но писать по нему Кимо будет только если человек уже писал вам или подписался, иначе рассылка пропускается (`skipped`).
- Через Business бот может писать только в **личные чаты, где были входящие сообщения за последние 24 часа** (`BusinessBotRights.can_reply`). Если окна нет или Telegram отклонил отправку, Кимо ничего не обходит (никаких userbot/Telethon): пишет причину в `last_status` и присылает вам **готовый текст для ручной отправки**.
- **Лучший вариант для ежедневных сообщений:** человек сам запускает Кимо по вашей ссылке `/bcast link` (`https://t.me/<бот>?start=sb_<ваш id>`). Тогда сообщения идут от имени самого бота (канал `bot`), без 24-часового окна. Отписка: слово «стоп».

**Правила:** максимум 1 сообщение в сутки на чат (`broadcast_max_per_day` в `user_settings`, общий для всех рассылок в этот чат); если человек пишет «стоп», «не пиши» и т.п., все рассылки на него отключаются и заново их можно создать только после его повторной подписки; повтор до 30 минут после назначенного времени, если ИИ или Telegram временно недоступны, потом статус `missed`/`failed`. Часовой пояс у каждой рассылки свой (по умолчанию Asia/Tashkent).

**Команды (право `broadcasts`):** `/bcast` — список, `/bcast add <chat_id> <ЧЧ:ММ> <дни> text <текст>` или `... ai <тема>` (например `ai спроси, как дела`), дни: `daily`, `weekdays`, `weekend`, `1-5`, `пн,ср,пт`; `/bcast on|off|del <id>`, `/bcast log` — история отправок, `/bcast chats` — кому можно писать, `/bcast link` — ссылка для подписки.

## Доступ пользователей: /grant

- `/grant <user_id> <дней>` — выдать или продлить доступ (роль `user`), только `ADMIN_ID`. Срок считается от текущего окончания, максимум 3650 дней. Пользователь получает сообщение с подсказкой, как подключить Кимо в Telegram Business.
- `/revoke <user_id>` — отозвать сразу (пользователь получает уведомление), `/grants` — активные доступы с датами.
- Хранится в таблице `access_grants` (`user_id`, `granted_by`, `expires_at`, `active`, история сохраняется). Доступы, выданные прежней версией через `sub_until`, при миграции v6 переносятся.
- Автоотзыв: задача APScheduler раз в 5 минут закрывает истёкшие доступы. Пользователю приходит напоминание за 1 день и сообщение об окончании, вам — уведомление об окончании. Сразу после отзыва перестают работать меню, ассистент, напоминания и ответы Business: проверка срока идёт при каждом сообщении, а не только по задаче.
- Без активного доступа бот отвечает: «Это личный бот… отправьте владельцу ваш ID» и присылает вам запрос с готовой командой `/grant <id> 30` (не чаще раза в сутки от человека).
- Оплата Stars/Click не тронута и выключена `SUBSCRIPTION_ENABLED=false`.

## Telegram Business: Кимо отвечает клиентам как AI-агент

**Что нужно сделать вручную (по API нельзя):**
1. @BotFather → ваш бот Кимо → Bot Settings → **Business Mode** включён (уже сделано).
2. У каждого, кто подключает Кимо (вы и пользователи после `/grant`), должен быть **Telegram Premium**: Настройки → Telegram Business → Чат-боты → выбрать Кимо → включить «Отвечать на сообщения».
3. Перезапустите Кимо (`./run.sh restart kimo`): он сам подпишется на `business_connection`, `business_message`, `edited_business_message`, `deleted_business_messages`. После подключения Кимо пришлёт подтверждение.

**Как работает**
- Ответы идут только с `business_connection_id` и только в личные чаты. Боты, группы и каналы игнорируются, на ваши собственные сообщения Кимо не отвечает.
- Если вы ответили клиенту вручную, Кимо молчит в этом чате `pause_hours` часов (по умолчанию 6). Свои сообщения (отправленные ботом) пауза не включают.
- Первое сообщение в чате начинается с «Здравствуйте! Я Кимо, AI-агент <имя>». Имя берётся из `/brules name` или из профиля Telegram. Если спросят «вы человек?», Кимо честно отвечает, что он AI (без обращения к модели).
- Ответ формирует Groq по вашим правилам (`/brules`): правила, информация о бизнесе, запреты, тон. Вопрос вне правил или просьба позвать человека: Кимо не выдумывает, пишет, что владелец свяжется, присылает вам уведомление со ссылкой на чат и замолкает в этом чате (пока вы не ответите или не истечёт пауза).
- Голосовые клиентов расшифровываются Whisper (до 3 минут, до 10 МБ).
- Контекст — последние 20 сообщений чата, журнал хранится 30 дней (чистится раз в сутки). Удалённые клиентом сообщения удаляются и из журнала.
- Антифлуд: не больше `flood_per_min` ответов на чат в минуту (по умолчанию 6) и общий лимит `BUSINESS_AI_PER_MIN`/`BUSINESS_AI_PER_DAY` на всех клиентов владельца, чтобы не съесть лимит Groq.
- Подарки, Stars и платежи через Business не используются.

**Команды (в личке с Кимо, право `business`):**
`/brules` — показать правила, `/brules prompt|info|ban|tone|name|pause|flood <значение>` — изменить; `/bchats` — чаты клиентов; `/pause` и `/resume` — выключить/включить Кимо во всех Business-чатах; `/pause <chat_id>` и `/resume <chat_id>` — исключить чат/вернуть.

## Роли, права пользователей и доходы

- **Роли людей:** `admin` (ваш `ADMIN_ID`) и `user` (получил доступ через `/grant`). Роли агентов (`admin/creator/agent`) — отдельная вещь, см. выше.
- **Данные изолированы:** в таблицах задач и финансов поле `user_id` (внутренний `users.id`), все запросы фильтруются по нему. В новых таблицах (бизнес-чаты, рассылки и т.д.) то же поле называется `owner_id`.
- **Флаги прав** (`user_perms`): `tasks`, `finance`, `reminders`, `business`, `broadcasts`, `assistant`. У `user` включены по умолчанию, админ может выключить: `/perm <user_id> finance off`, `/perm <user_id>` покажет все.
- **Только admin** (зашито в коде, выдать нельзя): `agents_manage` (создание и управление агентами), `tokens`, `other_users` (чужие данные), `system`, `grants`.
- Права проверяются и в меню (`PermMiddleware`), и в действиях ассистента (текст и голос), и в API Mini App.
- **Доходы:** `/income 5 млн зарплата`, кнопка «Добавить доход», голос («получил 300 долларов от клиента»). В таблице `expenses` поле `kind` (`income`/`expense`), суммы в UZS и USD. Сводка за период показывает доходы и баланс.

## Очередь запросов к ИИ

Все обращения к Groq идут через общую очередь процесса (`bot/ai/queue.py`): сначала владелец, потом клиенты и пользователи, потом фоновые задачи (рассылки, AI-советы). При 429 клиентские и фоновые запросы повторяются с задержкой 5/15/45 с (владельцу ошибка отдаётся сразу), дневной лимит не повторяется. Для пользователей (не владельца) действует лимит обращений: `USER_AI_PER_MIN` (6) и `USER_AI_PER_DAY` (150). Счётчики хранятся в памяти процесса и сбрасываются при перезапуске.


`downgrade 1` удаляет только новые таблицы, расходы и задачи остаются. Токены в `secrets` тоже сохраняются, потому что эта таблица была и раньше.

## Безопасность

- `.env` не попадает в git. Права: `chmod 600 .env data/bot.db*`.
- Токены ботов шифруются Fernet в таблице `secrets`. Ключ лежит только в `.env`.
- Сообщение с токеном Кимо удаляет сразу. Токены в группе не принимаются, в LLM не отправляются, в логах заменяются на `***`. Токен нового агента добавляется в фильтр логов прямо во время работы.
- SQL-запросы только параметризованные. Права агентов на таблицы проверяются в слое доступа к БД.
- В группе исполняются только сообщения `ADMIN_ID`. Задачи другим агентам может передавать только владелец.
- Антиспам `RATE_LIMIT_PER_MIN` работает на пользователя. Ввод проверяется: суммы, даты, длина текста, имена агентов, формат токена.

Что покрыто:

- атомарный захват задания двумя процессами и ограничение `depth`;
- права агентов на таблицы, шифрование токена;
- разбор решения диспетчера, флаг `SUBSCRIPTION_ENABLED`;
- группа: только владелец, удаление токенов;
- ответ агента реплаем, ассистент спрашивает Кимо о напоминаниях;
- полный цикл создания агента;
- миграции, бэкап и откат;
- всё, что было раньше: расходы, задачи, оплата, графики.

## Частые проблемы

| Симптом | Решение |
|---|---|
| Кимо не реагирует на сообщения в группе | Отключите privacy mode (BotFather → Group Privacy → Turn off), удалите бота из группы и добавьте снова |
| Окно агента закрылось сразу после запуска | Ошибка конфигурации (код 2) или агент выключен (код 3). Смотрите `./run.sh logs <агент>` |
| `Нет токена для …` | `python manage.py agents set-token <агент>` или переменная `<ИМЯ>_TOKEN` в `.env` |
| `TelegramConflictError: terminated by other getUpdates request` | Один токен у двух процессов: остался старый бот (`tmux kill-session -t tgbot`) или два агента с одним ботом |
| «Агент не ответил вовремя» | Агент не запущен или упал. Проверьте `./run_all.sh status` и `./run.sh logs <агент>` |
| «Задача остановлена: её передавали больше 3 раз» | Агенты перекидывали задачу друг другу. Скажите явно, кто должен её сделать |
| Токен в группе не удалился | Дайте Кимо в группе право удалять сообщения |
| «Слишком много запросов к ИИ» | Сработал лимит Groq free (см. таблицу лимитов) |
| `database is locked` | Не открывайте БД сторонними программами на запись при работающих агентах. `busy_timeout` равен 5 с |

## Структура

```
run_agent.py               запуск агента: python run_agent.py <имя>
run_all.sh / run.sh        все агенты / один агент в tmux с автоперезапуском
manage.py                  БД (бэкап, откат, восстановление) и агенты (список, токены, включение)
agents/*.json              стартовые карточки kimo, agent_builder, assistant
bot/
  runner.py                загрузка конфига агента, токен, запуск процесса
  main.py                  процесс Кимо: прежние функции + шина + диспетчер
  agents/registry.py       конфиги агентов, промпт с идентичностью
  agents/access.py         права агентов на таблицы (ScopedDB)
  agents/bus.py            шина tasks_queue, depth, фоновый воркер
  agents/generic.py        общий агент: assistant, agent_builder, будущие агенты
  agents/kimo.py           ответы Кимо другим агентам (без расходов)
  agents/cards.py          карточка нового агента
  agents/builder_flow.py   подтверждение, токен, запуск агента
  ai/llm.py                общий слой провайдеров LLM (сейчас только Groq)
  ai/groq_client.py        Groq: чат, поиск, Whisper, лимиты, usage-лог
  handlers/agents_admin.py команды владельца для агентов
  handlers/, services/     задачи, расходы, статистика, оплата (как раньше)
  db.py                    схема, миграции, бэкап, откат
```
