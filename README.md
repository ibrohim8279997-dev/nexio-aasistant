# Кимо и агенты

Мультиагентная система в Telegram на одном телефоне-сервере (Termux + Debian, без Docker, long polling).

- **Кимо** (`kimo`) — главный агент и диспетчер. Сам ведёт расходы, задачи и напоминания, остальную работу передаёт другим агентам.
- **Создатель агентов** (`agent_builder`) — по вашему описанию составляет карточку нового агента.
- **Ассистент** (`assistant`) — универсальный помощник: отвечает на вопросы, ищет в интернете (browser search Groq), а нужные данные запрашивает у Кимо.

У каждого агента свой Telegram-бот и свой процесс (`python run_agent.py <имя>`) в отдельном окне tmux, поэтому падение одного не задевает остальных. Все агенты используют один репозиторий, один venv, одну SQLite в режиме WAL и один `GROQ_API_KEY`.

## Что умеет Кимо (было и осталось)

| Раздел | Что умеет |
|---|---|
| Задачи | Текстом или голосом («завтра в 15:00 позвонить маме»): «Сегодня»/«Завтра», выполнено, перенос, удаление, напоминания |
| Расходы | Суммы в UZS и USD, категории, курс ЦБ (cbu.uz, кэш 1 час), итоги за день, 7 и 30 дней |
| Статистика | Графики расходов и задач, трекер выполнения и серия дней подряд |
| Подписка | Telegram Stars, 250 ⭐ за 30 дней. **Выключена флагом** `SUBSCRIPTION_ENABLED=false`, Click — выключенная заготовка |

## Как устроено

```
Владелец ──голос/текст──▶ Кимо (группа или личка)
                           │  Whisper → gpt-oss-120b решает, чья это задача
                           ├─ своя (расходы, задачи) → выполняет сам
                           ├─ чужая → пишет задание в tasks_queue → «👉 Задачу взял Ассистент»
                           └─ неясно → один короткий вопрос
Агент (свой процесс) ◀── опрашивает tasks_queue раз в 1,5 с, забирает задание атомарно,
                          выполняет и отвечает в группу от своего имени реплаем на исходное сообщение
```

- **Конфиг агента** хранится в таблице `agents`: имя, роль, системный промпт, модели (провайдер, текстовая модель, Whisper, поиск), разрешённые таблицы и команды, запреты. Стартовые карточки лежат в `agents/*.json` и попадают в БД при первом запуске. Дальше источник правды — БД.
- **Идентичность.** В промпт каждого агента подставляются его имя, роль, запреты и список остальных включённых агентов с ролями, всё из таблицы `agents`. На вопрос «как тебя зовут» Кимо отвечает «Кимо».
- **Права на таблицы** проверяются в слое доступа к БД (`bot/agents/access.py`, обёртка `ScopedDB`), а не только в промптах:
  - агент получает только таблицы из `allowed_tables`;
  - таблицы `expenses`, `payments` и `secrets` доступны только Кимо, что бы ни было написано в конфиге;
  - у нового агента по умолчанию нет доступа ни к одной таблице, кроме собственных `agent_<имя>_*`;
  - на запросы других агентов через шину Кимо данные о расходах не выдаёт.
- **Шина заданий** — таблица `tasks_queue`. Поле `depth` растёт на 1 при каждой передаче между агентами. Если передач больше 3, задача получает статус `failed` и возвращается владельцу с пояснением (защита от зацикливания).
- **В группе** исполняются только сообщения владельца (`ADMIN_ID`). Сообщения других участников игнорируются. Если в группе появляется токен, он тут же удаляется. Если сообщение адресовано другому агенту (упоминание `@бот` или реплай на его сообщение), Кимо его не перехватывает.

## Установка (Termux + Debian)

### 1. Termux и Debian

```bash
# Termux (из F-Droid)
pkg update && pkg upgrade -y
pkg install -y proot-distro openssh tmux termux-api
termux-wake-lock
proot-distro install debian
proot-distro login debian
# Debian
apt update && apt install -y python3 python3-venv python3-pip git tmux
```

Отключите для Termux оптимизацию батареи: Настройки Android → Приложения → Termux → Батарея → «Без ограничений».

**SSH.** В Termux задайте пароль (`passwd`) и запустите `sshd`. С компьютера: `ssh -p 8022 <любое_имя>@<IP_телефона>`.

### 2. Код

```bash
cd ~
git clone https://github.com/ibrohim8279997-dev/nexio-aasistant.git
cd nexio-aasistant
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
```

### 3. Боты в @BotFather (делается вручную, по API нельзя)

1. Создайте три бота командой `/newbot`: для Кимо, для Ассистента и для Создателя агентов.
2. **Кимо: отключите privacy mode.** `/mybots` → бот Кимо → Bot Settings → Group Privacy → **Turn off**. Иначе Кимо видит в группе только команды и упоминания. Если бот уже был в группе, удалите его и добавьте заново, чтобы настройка применилась.
3. У остальных агентов privacy mode оставьте включённым: в группе они отвечают на упоминание `@бот` и на реплай, а задания получают через шину.
4. Создайте группу и добавьте в неё всех ботов. **Сделайте Кимо администратором с правом удалять сообщения**, чтобы он мог стирать случайно отправленные в группу токены.
5. Каждому боту отправьте `/start` в личке. Без этого бот не сможет написать вам первым.

### 4. `.env` и токены

```bash
cp .env.example .env
python gen_key.py        # строку ENCRYPTION_KEY=... вставьте в .env
nano .env                # GROQ_API_KEY, ADMIN_ID
chmod 600 .env
```

Токены ботов лучше хранить зашифрованно в БД, а не в `.env`:

```bash
python manage.py agents set-token kimo            # ввод скрыт, токен шифруется Fernet в таблице secrets
python manage.py agents set-token assistant
python manage.py agents set-token agent_builder
```

Можно и через `.env`: `KIMO_TOKEN`, `ASSISTANT_TOKEN`, `AGENT_BUILDER_TOKEN`. Старая переменная `BOT_TOKEN` по-прежнему работает для Кимо.

Порядок поиска токена: переменная из `.env`, затем `secrets`, для Кимо в последнюю очередь `BOT_TOKEN`.

| Переменная | Значение |
|---|---|
| `GROQ_API_KEY` | один ключ на всех агентов (https://console.groq.com/keys) |
| `ADMIN_ID` | ваш Telegram ID. Команды исполняются только от него |
| `ENCRYPTION_KEY` | ключ Fernet. **Сохраните копию**, без него токены в БД не расшифровать |
| `DB_PATH` | `data/bot.db` |
| `SUBSCRIPTION_ENABLED` | `false` — бот личный; `true` — включена продажа подписки Stars |
| `SEARCH_ENABLED` | `true` — веб-поиск разрешён агентам, у которых в конфиге `"search": true` |
| `CLICK_ENABLED` | `false` (Click — заготовка) |

Модели и провайдер берутся из конфига агента (`models`), а не из кода и не из `.env`.

### 5. Запуск всех агентов

```bash
chmod +x run.sh run_all.sh
./run_all.sh              # все включённые агенты из таблицы agents, каждый в своём окне tmux (сессия agents)
./run_all.sh status
./run_all.sh stop | restart
tmux attach -t agents     # окна агентов: Ctrl+B, затем номер окна; выйти — Ctrl+B, затем D
```

Один агент:

```bash
./run.sh start assistant      # новое окно tmux; при падении агент перезапустится через 5 с
./run.sh stop assistant
./run.sh restart assistant
./run.sh logs assistant       # logs/assistant.log
./run.sh fg assistant         # в текущем терминале (отладка)
```

Коды выхода `run_agent.py`:

| Код | Значение | Что делает `run.sh` |
|---|---|---|
| 0 | штатная остановка | перезапускает |
| 1 | падение | перезапускает |
| 2 | ошибка конфигурации (нет токена, плохой `.env`) | не перезапускает |
| 3 | агент выключен или не найден | не перезапускает |

Ошибки ищите в `logs/<агент>.log`.

```bash
chmod 600 data/bot.db*
```

**Автозапуск после перезагрузки (Termux:Boot):**

```bash
mkdir -p ~/.termux/boot
cat > ~/.termux/boot/start-agents.sh <<'EOF'
#!/data/data/com.termux/files/usr/bin/sh
termux-wake-lock
proot-distro login debian -- bash -c "cd ~/nexio-aasistant && ./run_all.sh"
EOF
chmod +x ~/.termux/boot/start-agents.sh
```

### Переход со старой версии (один бот)

```bash
./run.sh stop 2>/dev/null; tmux kill-session -t tgbot 2>/dev/null   # остановить старого бота
git pull && . .venv/bin/activate && pip install -r requirements.txt
python manage.py db backup                                          # ручной бэкап (автоматический тоже будет)
./run_all.sh
```

При первом запуске применяется миграция №2: она добавляет таблицы `agents` и `tasks_queue`. Перед миграцией делается бэкап `data/backups/bot-<дата>-before-v2.db`. Расходы и задачи миграция не трогает.

## Добавление агента

**Через Кимо (основной способ):**

1. Скажите или напишите Кимо: «Создай агента для …: что делает, что можно, что нельзя, насколько всё конфиденциально».
2. Кимо передаёт описание создателю агентов. Тот составляет карточку: имя, роль, промпт, нужен ли Whisper и поиск, предлагаемые права, запреты. Модель только **предлагает**: расходы, платежи и секреты в карточку не попадают никогда.
3. Кимо показывает карточку. Вы выбираете: «Да, с предложенными правами», «Да, без доступа к таблицам» или «Отмена». Без подтверждения агент не запускается.
4. Создайте бота в @BotFather и **пришлите токен Кимо в личку**. Кимо удалит сообщение и сохранит токен зашифрованным. В группе токены не принимаются.
5. Кимо запустит агента в новом окне tmux, проверит, что тот отвечает через шину, и сообщит: «Агент работает».

Команды владельца в Кимо:

| Команда | Что делает |
|---|---|
| `/agents` | список агентов и их статус |
| `/agentperm имя tasks,rates_cache` | задать таблицы агенту (`-` — без доступа) |
| `/agenton имя`, `/agentoff имя` | включить и запустить / выключить и остановить |
| `/agenttoken имя токен` | передать токен, если его ждут несколько агентов |

**Вручную:**

```bash
cp agents/assistant.json agents/staff_bot.json && nano agents/staff_bot.json   # name, role, prompt, models, права
python manage.py agents add agents/staff_bot.json      # добавится выключенным
python manage.py agents set-token staff_bot
python manage.py agents enable staff_bot
./run.sh start staff_bot
```

Прочие команды: `python manage.py agents list | show <имя> | sync [имя] | enable | disable`. `sync` перечитывает `agents/*.json` в БД и сохраняет `enabled` и `bot_username`.

## Лимиты Groq (бесплатный план)

| Модель | Запросов в минуту | Запросов в день | Токенов в минуту | Токенов в день |
|---|---|---|---|---|
| `openai/gpt-oss-120b` | 30 | 1000 | 8 000 | 200 000 |
| `whisper-large-v3-turbo` | 20 | 2000 | — | — |

Лимит общий на все агенты, потому что ключ один. Как бот с ним работает:

- **Учёт:** каждый процесс сам считает запросы и токены и читает заголовки `x-ratelimit-remaining-*` из ответов Groq. Если токенов почти не осталось, агент ждёт сброса окна.
- **Ответ 429:** агент ждёт `retry-after` (до 20 с) и повторяет запрос. Если ждать дольше, вы получите сообщение, через сколько попробовать снова.
- **Поиск:** у ассистента — не больше одного шага поиска на запрос. Число поисков внутри шага ограничено промптом (`max_searches` в конфиге, по умолчанию 2) и `reasoning_effort=low`.
- **Замер расхода:** каждый вызов модели пишется в `logs/usage-<агент>.log`: prompt/completion/total токены, число поисков, `x-ratelimit-remaining-tokens`, `x-ratelimit-remaining-requests`. Тексты и ключи туда не попадают. Пример: `grep "search=True" logs/usage-assistant.log`.

## Подписка

Код Telegram Stars остался полностью: счёт, `pre_checkout_query`, `successful_payment`, продление, напоминание за 3 дня. Click остаётся заготовкой.

- `SUBSCRIPTION_ENABLED=false` (по умолчанию): бот личный. Работает владелец и те, кому вы выдали доступ через `/grant`. Остальные видят «Это личный бот», без кнопок оплаты. Счета не выставляются.
- `SUBSCRIPTION_ENABLED=true`: продажа включена. Перезапустите Кимо: `./run.sh restart kimo`.
- Админ-команды не изменились: `/grant`, `/revoke`, `/users`, `/stats`.

```bash
./run_all.sh stop

```

**Миграции БД:**

```bash
python manage.py db version            # текущая версия схемы
python manage.py db downgrade 1        # удалить agents и tasks_queue (перед откатом делается бэкап)
python manage.py db backups            # список бэкапов
python manage.py db restore data/backups/bot-...-before-v2.db --yes   # полное восстановление из бэкапа
```

`downgrade 1` удаляет только новые таблицы, расходы и задачи остаются. Токены в `secrets` тоже сохраняются, потому что эта таблица была и раньше.

## Безопасность

- `.env` не попадает в git. Права: `chmod 600 .env data/bot.db*`.
- Токены ботов шифруются Fernet в таблице `secrets`. Ключ лежит только в `.env`.
- Сообщение с токеном Кимо удаляет сразу. Токены в группе не принимаются, в LLM не отправляются, в логах заменяются на `***`. Токен нового агента добавляется в фильтр логов прямо во время работы.
- SQL-запросы только параметризованные. Права агентов на таблицы проверяются в слое доступа к БД.
- В группе исполняются только сообщения `ADMIN_ID`. Задачи другим агентам может передавать только владелец.
- Антиспам `RATE_LIMIT_PER_MIN` работает на пользователя. Ввод проверяется: суммы, даты, длина текста, имена агентов, формат токена.

## Частые проблемы

| Симптом | Решение |
|---|---|
| Кимо не реагирует на сообщения в группе | Отключите privacy mode (BotFather → Group Privacy → Turn off), удалите бота из группы и добавьте снова |
| Окно агента закрылось сразу после запуска | Ошибка конфигурации (код 2) или агент выключен (код 3). Смотрите `./run.sh logs <агент>` |
| `Нет токена для …` | `python manage.py agents set-token <агент>` или переменная `<ИМЯ>_TOKEN` в `.env` |
| `TelegramConflictError: terminated by other getUpdates request` | Один токен у двух процессов: остался старый бот (`tmux kill-session -t tgbot`) или два агента с одним ботом |
| «Агент не ответил вовремя» | Агент не запущен или упал. Проверьте `./run_all.sh status` и `./run.sh logs <агент>` |
| «Задача остановлена: её передавали больше 3 раз» | Агенты перекидывали задачу друг другу. Скажите явно, кто должен её сделать |
| Токен в группе не удалился | Дайте Кимо в группе право удалять сообщения |
| «Слишком много запросов к ИИ» | Сработал лимит Groq free (см. таблицу лимитов) |
| `database is locked` | Не открывайте БД сторонними программами на запись при работающих агентах. `busy_timeout` равен 5 с |

## Структура

```
run_agent.py               запуск агента: python run_agent.py <имя>
run_all.sh / run.sh        все агенты / один агент в tmux с автоперезапуском
manage.py                  БД (бэкап, откат, восстановление) и агенты (список, токены, включение)
agents/*.json              стартовые карточки kimo, agent_builder, assistant
bot/
  runner.py                загрузка конфига агента, токен, запуск процесса
  main.py                  процесс Кимо: прежние функции + шина + диспетчер
  agents/registry.py       конфиги агентов, промпт с идентичностью
  agents/access.py         права агентов на таблицы (ScopedDB)
  agents/bus.py            шина tasks_queue, depth, фоновый воркер
  agents/generic.py        общий агент: assistant, agent_builder, будущие агенты
  agents/kimo.py           ответы Кимо другим агентам (без расходов)
  agents/cards.py          карточка нового агента
  agents/builder_flow.py   подтверждение, токен, запуск агента
  ai/llm.py                общий слой провайдеров LLM (сейчас только Groq)
  ai/groq_client.py        Groq: чат, поиск, Whisper, лимиты, usage-лог
  handlers/agents_admin.py команды владельца для агентов
  handlers/, services/     задачи, расходы, статистика, оплата (как раньше)
  db.py                    схема, миграции, бэкап, откат
```
